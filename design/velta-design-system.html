Design principles

  • No pure black or white. Every surface stops short of #000/#fff — dark canvas #0f0f14 with #f2f2f5 ink, light #f4f4f4 with #16181d. Softer on OLED, avoids halation, and keeps the brutal theme's hard offset shadows readable ink (#121017), not void.
  • Contrast carries the hierarchy. Text/body pairs target WCAG AA, most hit AAA (table below). The known weak spots: light-theme text-dim 4.26 (AA only for large text) and light accent 3.01 (UI/large use only) — fix or accept deliberately.
  • Accent is a verb. --accent marks actions, links, unread state — nothing else. Status never borrows it: --green for presence/verified, --danger for destructive, timestamps use dedicated meta greys (--text-meta-in/out), never accent, because accent-blue meta reads as clickable.
  • Hover changes surfaces, never text. Interactive elements get --bg-hover / --bg-active overlays; text color stays put (and touch devices have no hover at all — every hover affordance has a press equivalent).
  • One stack, one grid. System UI font everywhere (no webfont, no per-platform tuning); 2px spacing grid with three gap tiers and four padding tiers; half-pixel type steps are deliberate (compact ladder), documented not accidental.
  • Dark is the primary theme. Light derives from it — any token a theme doesn't override is inherited from dark (flagged above), which is why --accent-2/--green/--danger on light are marked "contrast unverified". Brutal is dark-only by design.
  • The shell owns its scaling. text-size-adjust 100%, Android WebView textZoom pinned to 100, UI scale applied by Velta (applyUiScale), env(safe-area-inset-*) on every bar — no browser/OS text inflation surprises.
