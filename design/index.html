Component contracts

How the shared controls are meant to be used — this resolves the ghost-button/link ambiguity from the design review (#182). States everywhere: hover changes surfaces, never text; keyboard focus is a 2px --focus-ring outline; pressed fills use --bg-active / --accent-active.

Button — primary.btn-primaryThe one filled accent action per view (accent fill, --on-accent ink). One per dialog foot or screen; never in lists.
Button — text (tertiary).btn-textCompact accent-text action for rows, footers and secondary choices. It is a BUTTON, not a link: use it for something that happens (Retry, Use for sending), never inline inside a sentence. Borderless — the accent text at weight 600 is the affordance.
Button — destructive.btn-text + --danger inkDestructive = .btn-text colored var(--danger) (Remove, Delete). No filled red variant: destructive is a choice, not a destination — the confirm dialog carries the weight. Red fills are reserved for the call decline control.

Button states: default → hover (--bg-hover on ghost/tonal, --accent-hover on fills) → pressed (--bg-active / --accent-active) → focus-visible (2px --focus-ring, offset 2px) → disabled (not-allowed cursor, --border edge, dimmed ink — see .ivc-btn, the reference implementation). There is no button-level loading state: async actions disable or move progress to the surface it belongs to (corner pill, transfer pill, steps list) — buttons stay truthful.

Design principles

  • No pure black or white. Every surface stops short of #000/#fff — dark canvas #0f0f14 with #f2f2f5 ink, light #f4f4f4 with #16181d. Softer on OLED, avoids halation, and keeps the brutal theme's hard offset shadows readable ink (#121017), not void.
  • Contrast carries the hierarchy. Text/body pairs target WCAG AA, most hit AAA (table below). The one accepted spot: light-theme accent 3.01 (UI/large use only); light text-dim (4.93) and green (3.58) were fixed in the contrast pass.
  • Accent is a verb. --accent marks actions and links — nothing else. Unread is a status, not an action: badges ride --accent-2 with --on-badge ink. Status never borrows accent either: --green for presence/verified, --danger for destructive, timestamps use dedicated meta greys (--text-meta-in/out), because accent-blue meta reads as clickable.
  • Hover changes surfaces, never text. Interactive elements get --bg-hover / --bg-active overlays; text color stays put (and touch devices have no hover at all — every hover affordance has a press equivalent).
  • One stack, one grid. System UI font everywhere (no webfont, no per-platform tuning); 2px spacing grid with three gap tiers and four padding tiers; half-pixel type steps are deliberate (compact ladder), documented not accidental.
  • Dark is the primary theme. Light derives from it — any token a theme doesn’t override is inherited from dark (flagged in the cards). Light overrides the status colors so they pass as text: --green 5.51 AA, --danger 5.33 AA, --text-dim 5.04 AA. Still inherited/UI-grade on light: --accent-2 3.40 and raw --accent 3.01 — normal-size accent text uses --accent-text. Brutal is dark-only by design.
  • The shell owns its scaling. text-size-adjust 100%, Android WebView textZoom pinned to 100, UI scale applied by Velta (applyUiScale), env(safe-area-inset-*) on every bar — no browser/OS text inflation surprises.
