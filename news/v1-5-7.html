Velta 1.5.7: Loop transfers that finish, a composer in one row, and a Dash that explains itself

27 November 2026 · 4 min read

Two-way Loop transfers no longer freeze at 99%, the desktop composer collapses to a single armed row, and the Dash card learns to explain itself to Delta Chat users — and stops showing ghost copies after a profile is remade. Plus image Copy/Save in the message menu, the sealed-vCard import fix, a folder size pre-flight, and a keychain scoped per identity.

1.5.7 is a repair release with three things you will notice the first time you open a chat: a transfer that was stuck at 99% now lands, the composer no longer rearranges itself when you start typing, and the Dash card a Delta Chat user sees next to your file says what it is — and, in Velta, disappears when it should.

Transfers that finish

Two-way Loop copies could stall at 99%: the last frames of a dying session were never re-sent, so the receiver waited on data that had already been lost. Outbound texts that went unacked are now re-sent, and a live transfer is labeled Sending until the ack arrives instead of reporting done early. Progress repaints in place — the card fills to 100% where it sits rather than jumping away — and sealed sends finish their last chunk instead of hanging on the stream.

Files are now streamed while they copy instead of buffered whole, a received file is sealed off the session reader so a closed session can't read past it, and the Dash copy is honest about failure: Android enforces the same file cap as desktop, and when a fetch fails the card says so instead of reporting success. The transfer limit is printed as the real 2 GB, not "any size". The card's own meta text now passes AA on the outgoing bubble.

The composer moves to one row

The desktop composer stopped waiting for the first keystroke to expand. At every width it is one flex row: the field and the tools side by side, send in a fixed place from the moment a chat opens. Send shows its state — it fills with the accent color while there is text in the field and goes back to the quiet outline arrow when empty — so one glance tells you the message is armed.

Stickers leave the composer entirely and live in the attach menu, where the phone already kept them. And while a video copies, the strip shows the video itself instead of a placeholder — a preview that renders as it lands.

The Dash explains itself

The transfer card now carries a line that explains the Dash to a Delta Chat user — what the board is, why a file arrived there — and Velta hides that explainer for its own users, who already know. On Android the card's row verbs became Save and Share instead of Show in folder, which has no meaning on a phone. Swipe-to-reply and swipe-back now work on Dash cards, the header badge shrank to an icon-only accent button, and the Prism header goes full-bleed behind it. Byteless media shows its kind tile instead of an empty card.

A quieter fix: after a profile is recreated, persisted Dash copies are revalidated, so a Received card can no longer linger for a file that no longer exists.

Images you can keep

The message menu gained Copy image and Save image — the picture, not the message. On Android Tauri, Copy goes through the FileProvider as real ClipData, so it pastes into other apps as an image rather than a path. And the shared-contact glitch is fixed: a .vcf sealed as an attachment is now parsed and imported through the seal-aware blob reader, so a vCard that arrived encrypted no longer opens as raw bytes.

Before you send

Folders get a size pre-flight. A folder over 512 MB warns before it is zipped onto the send; a folder over the engine's 2 GB transfer limit is refused outright rather than failing mid-stream. You find out at pick time, not at 99%.

Also in this release

  • The keychain is scoped per identity — the database DEK credential is minted for the profile it unlocks, which is the root cause of the bricked-profile bug; the keychain helpers are gated off Android, where the credential store is a different shape.
  • A quieter bubble — the KMP client's VXFER1 / VXFER-RESEND ticket lines no longer leak into message bubbles.
  • 1:1 header wears the contact's Prism hue — the personal accent on a one-to-one chat, a follow-up to #519.
  • Windows installers build on PRs — a PR to master now builds the Windows bundle in CI instead of only on merge.
  • Sealed vCard import is covered — the parse_vcard core op guards its own call line, so a regression there fails a test, not a user.
  • One webxdc chip keeps its copy button — the sender chip on a webxdc bubble no longer swallows the copy action.
  • 4 MiB range cap — a blobfile Range answer is capped at 4 MiB, so a single fetch can't hold a connection open.

Under the hood

Attachment crypto streams instead of buffering: each chunk is decrypted once and encrypted in place, aarch64 uses hardware AES-GCM, and the crypto path runs at opt-level 3. The 99% stall, the sealed-send finish, and the cheapened chunk stream are the same change seen from three sides.
